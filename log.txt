    fix(chat): detect initial connected state on mount for reconnect tracking
    
    hasConnectedRef started as false. When Chat mounts after App.tsx already
    established the WebSocket connection, the initial CONNECTED event is missed.
    On the first real reconnect the handler saw hasConnectedRef=false and treated
    it as 'initial connect', skipping the loadHistory re-run that would fetch
    messages sent during the outage.
    
    Fix: check deliveryService.getConnectionState() on mount and pre-set
    hasConnectedRef=true if already connected, so the very first reconnect
    correctly triggers setReconnectCount and the subsequent history re-fetch.
